# Decor Options — документація

Сторінка **Decor Options** (розділ PROCESS) показує 3 вкладки з опціями декору
партнерів-виробників. Контент кожної вкладки тягнеться напряму з сайта виробника,
рендериться у **Shadow DOM** (повна ізоляція їхніх стилів, на всю ширину, без iframe),
кешується і оновлюється раз на добу.

---

Усі шляхи — відносно кореня теми `home-boys-2`.

| Файл | Тип | Призначення |
|------|-----|-------------|

| `decor-options-template.php` | **новий** | Шаблон сторінки (хедер, 3 таби, повноширинні панелі) |
| `assets/js/decor-options.js` | **новий** | Перемикання табів + відновлення інтерактиву кожного донора в Shadow DOM |
| `assets/css/decor-options.css` | **новий** | Reset кнопок-табів + стилі панелей (стилі самих табів — з `style.css`) |
| `functions.php` | **змінений** | Додано `require .../inc/decor-options.php` |
| `DECOR-OPTIONS.md` | **новий** | Ця документація |

### Зміни в БД WordPress (повторити на проді вручну або через WP-CLI)

Файлів недостатньо — на проді треба також:

1. **Створити сторінку** «Decor Options» і призначити їй шаблон:
   ```bash
   wp post create --post_type=page --post_title="Decor Options" --post_status=publish --porcelain
   wp post meta update <ID> _wp_page_template decor-options-template.php
   ```
2. **Додати її в меню** під пункт PROCESS:
   ```bash
   wp menu item add-post <menu> <ID> --parent-id=<id_пункту_PROCESS>
   ```
3. Кеш (`wp_options` → `hb2_decor_cache_*`) **створюється сам** при першому відкритті
   вкладки або першому запуску cron — переносити з локалки не треба.

## 2. Як парсяться ці три сторінки

Кожен донор обробляється однаково (`hb2_decor_extract()` в `inc/decor-options.php`):

1. **Завантаження** — `wp_remote_get()` тягне HTML сторінки виробника (server-side, тому
   без CORS).
2. **Вирізання сміття** — регуляркою видаляються `<script>`, `<noscript>`, коментарі
   (інакше libxml ламає інлайн-JS і він протікає текстом).
3. **Витяг контентної зони** — `DOMDocument` + XPath-селектор бере лише потрібний блок,
   **без** хедера / меню / футера виробника:
   | Вкладка | Донор | Платформа | Селектор контенту |
   |---------|-------|-----------|-------------------|
   | Golden West Homes | `decor.goldenwestalbany.com` | кастомний PHP (Fat-Free) | `//div[@class~="app-container"]` |
   | Marlette Homes | `claytonhermiston.com/decor/` | WordPress | `//main[@id="main"]` |
   | Cavco Nampa / Fleetwood | `cavcoidaho.com/manufactured-home-decor/` | WordPress + Elementor | `//div[@data-elementor-type="wp-page"]` |
4. **Чистка** — всередині блоку видаляються `<script>/<form>/<iframe>` і будь-які
   `elementor-location-header/footer`.
5. **Абсолютизація URL** — усі відносні `src/href/srcset/poster/data-src` та `url()` в
   інлайн-стилях переписуються на повний `https://<домен_виробника>/...`. Картинки в їхніх
   CSS-файлах резолвляться браузером самі (відносно CSS на їхньому домені).
6. **Стилі** — збираються всі `<link rel=stylesheet>` донора + інлайн `<style>` з `<head>`.
7. **Кеш** — результат `{ html, styles[], hash, fetched, checked, changed }` пишеться в
   `wp_options` (`hb2_decor_cache_<key>`, autoload=false).

**Віддача на фронт:** REST `GET /wp-json/hb2/v1/decor/<key>` повертає кеш. JS створює
Shadow DOM, вставляє `<link>` стилів виробника + HTML. Стилі виробника живуть лише в
shadow root і не торкаються нашої теми.

**Відновлення інтерактиву** (їхній JS ми не виконуємо — пишемо свій у `decor-options.js`):
- Golden West — ліве меню `[data-option="#панель"]`: розкриття підменю + показ панелі.
- Marlette — таби Bootstrap 5 (`data-bs-toggle/target`): Interior / Exterior.
- Cavco — таби Bootstrap 4 (категорії) + кошик «Select / Final Selection».

## 3. Оновлення раз на добу + перевірка змін

- **WP-Cron** подія `hb2_decor_daily_refresh` (інтервал `daily`) перефетчує всі 3 донори.
- **Зміни-детектор:** після парсингу рахується `md5(html)`. Якщо хеш збігається з кешем —
  оновлюється лише час перевірки (`checked`), сам контент **не переписується**. Якщо хеш
  інший — зберігається новий снапшот і ставиться `changed`. Тобто на нашій сторінці дані
  оновлюються лише коли вони реально змінились у донора.
- **Захист від поломки:** якщо донор недоступний або контентну зону не знайдено —
  лишається останній робочий кеш (сторінка не біліє), у `error` пишеться причина.
- **Ручний рефреш** (для адміна): `?hb2_decor_refresh=all` або `?hb2_decor_refresh=cavco`
  на будь-якій сторінці; або `wp eval 'hb2_decor_refresh_all();'`.
- **Нюанс Cavco:** генерує випадкові `data-id` зразків при кожному запиті, тому його хеш
  щоразу різний і кеш переписується щодоби навіть без реальних змін (нешкідливо).

## 4. Навантаження на сайт

**Раз на добу (cron):** 3 вихідні HTTP-запити (~70–190 КБ кожен) + DOM-парсинг
(десятки мс на сторінку) + запис 0–3 рядків `wp_options`. Практично непомітно.

**На відвідувача:** при відкритті вкладки — 1 REST-запит, що читає **кеш** (без вихідних
запитів до донора). HTML віддається з нашого сервера; а CSS і картинки виробника
вантажаться браузером **напряму з їхніх серверів** (їхній трафік, не наш). Сама сторінка
додає лише один невеликий CSS + JS (тільки на цьому шаблоні, через `is_page_template`).

**Пам'ять:** кеш у `wp_options` з `autoload=false` — не вантажиться на кожен запит,
читається лише через REST.

**Важливо для прода:** стандартний WP-Cron спрацьовує від трафіку. На сайтах з низьким
трафіком добова подія може запізнюватись до першого візиту. Для надійності — реальний
system-cron + `define('DISABLE_WP_CRON', true);` у `wp-config.php`:
```
*/15 * * * * curl -s https://thehomeboys.com/wp-cron.php?doing_wp_cron >/dev/null 2>&1
```
